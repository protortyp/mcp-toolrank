# What changes when a small retriever sees real MCP tools

The first pilot trained a 33.36M encoder on 88 original requests and fell behind other models on ToolRet. The follow-up kept the same encoder capacity and prepared 5,098 training requests from public MCP data. Each retained target name and description had to match a pinned source file, and its license file had to match the recorded Git blob. Tool and provider overlap checks separated training and development from the frozen test. [Data and protocol](MODERN_MCP.md)

On 1,549 answerable ETOM requests ranked against 2,375 tools, the model reached 90.13% nDCG@10 with compact descriptions, compared with 88.95% for the same untuned base and 81.42% for the same-size ToolScout. The paired gain over BGE was 1.18 points, with a provider-cluster interval of 0.53 to 1.85 points. JSON representation changed the effect. Native MCP schemas put the candidate at 87.98%, essentially tied with BGE. The 595.78M Tool-Embed specialist still leads both representations. [Per-model results and paired intervals](../results/etom)

The benchmark includes 91 infeasible requests. A threshold estimated on separate authored development requests accepted 32.97% of infeasible test requests with compact descriptions and 62.64% with MCP JSON. Those rates constrain deployment claims about abstention. The benchmark analyzes static retrieval, so it does not establish tool-call correctness or end-to-end agent performance. [Abstention results](../results/etom/candidate-plain.json)

You can reproduce the experiment locally from pinned model and data revisions. The locked `uv` environments use CPU PyTorch for the two agent examples and ONNX, and CUDA 12.8 for training. The package keeps weights, upstream provenance, code, and evaluation records separate. [Run instructions](../README.md) · [Model card](MODERN_MODEL_CARD.md)

The full ToolRet run reached 28.54% nDCG@10 over 44,453 tools and 7,961 queries, close to the same-size baselines. Independent NumPy ranking reproduced the compact-description ETOM result and yielded 90.24% and 90.36% nDCG@10 for the two other prespecified training seeds. The candidate's CPU p50 was 12.71 ms on the measured workload. The smaller 17.39M experiment ran at 3.52 ms p50, with 89.03% ETOM nDCG@10 and weaker abstention on compact descriptions.
